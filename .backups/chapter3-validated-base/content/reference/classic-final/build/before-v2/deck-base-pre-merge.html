Architecture · Vue d'ensemble

La solution est une chaîne en trois zones : le poste, GitHub et Azure

Voici la solution, en une seule image.

Zone un : le poste du développeur. On code, et on pousse sur GitHub.

Zone deux : GitHub Actions. Le pipeline teste, contrôle, et construit l'image.

Zone trois : Azure. ArgoCD déploie sur le cluster AKS, et Grafana surveille. On va zoomer sur chaque zone.

Analyse de sécurité Construction et publication

Voici une vue de synthèse en huit étapes. Chaque pipeline prend celles qui le concernent.

Gitleaks cherche des secrets. SonarCloud et Semgrep analysent le code. Dependency-Check vérifie les bibliothèques. Checkov vérifie l'infrastructure. Docker construit l'image, Trivy la scanne, puis elle part dans ACR. Les tests de chaque composant tournent aussi.

Six contrôles de sécurité. Le compteur passe de zéro à six.

Parcours d'un changement · Analyse bloquante 3 sur 3

Trivy arrête une image avec une faille grave qui a déjà un correctif

- name: Trivy image scan
  uses: aquasecurity/trivy-action  # v0.36.0
  with:
    scanners: vuln
    severity: HIGH,CRITICAL
    ignore-unfixed: true
    exit-code: '1'
    trivyignores: .trivyignore.yaml

Extrait de .github/workflows/ci-backend.yaml (branche staging), lignes simplifiées

Troisième exemple : Trivy, qui scanne l'image Docker.

Une faille HIGH ou CRITICAL arrête le pipeline. Mais une faille sans correctif ne bloque pas : c'est ignore-unfixed. Et deux exceptions sont écrites, avec une date de fin. Trivy réduit le risque, sans garantir zéro faille.
